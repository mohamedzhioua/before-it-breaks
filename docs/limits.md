# Limits

For anyone deciding how much weight to give an audit made with this kit. These are the honest limits of the method and of this version.

- **Proven on code, not measured.** The method has been used on code only. Its findings are PROVEN-STATIC or UNPROVEN: breaking sizes are calculated from the code, the configuration and documented limits, and the skeptics correct many of them, but a calculation can still be wrong. The measure step that would confirm them is [designed, not yet proven](measuring.md).
- **One reference system.** The method has been used end to end on one private audit of a multi-repository Node.js/TypeScript system using MongoDB, Redis and Kubernetes. Nothing about that system ships with the kit. Other stacks are untested; there is one public pilot (connect-mongo, lite scope; an excerpt is in [`examples/`](../examples/README.md)), and the Novu worked example is still planned.
- **Not deterministic.** Two runs on the same code will not find exactly the same candidates or reach exactly the same verdicts. Trust rests on what can be re-checked (pinned citations, receipts anyone can re-run, recorded overrides), not on what one model believes.
- **One model family.** All three skeptics differ in lens and each works in its own context, but they share a model family, so they may share blind spots. By default the verifier uses another, smaller model, and it checks evidence mechanically, not merit.
- **One run is not exhaustive; repeated runs find more.** A single hunt does not find everything. The authors of [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) report this for their own AI audit skill: one run does not cover everything, and running it again finds more. Expect the same here, and treat "no finding" as "nothing found in this run", never as "nothing there". More hunt runs add candidates, and each new one goes through the same checks.
- **Newer lens items are unproven.** The lens items for poison records and head-of-line blocking, detached work, unsafe replay, aggregate limits, cache stampedes, key cardinality and superlinear parsing have not yet been seen in practice: they produced none of the seven candidates of the first public pilot.
- **Scope sets coverage.** Hunters read the groups you define. Code outside every group, repos marked `context_only`, and topics in `out_of_scope` are not hunted. There is no completeness guarantee.
- **Costs are not predictable precisely.** Time and AI usage grow with the number of repos, groups and candidates, and multi-agent phases use far more than ordinary chat. Record what each phase actually used in the run log; the kit gives no fixed figures.
- **Models change.** The kit was built and used with Claude models available in late 2026. Other and later models are untested; the config uses aliases so it keeps working, but results may differ.
- **Experimental parts.** The recommend phase (module plans, decision records, roadmap) is experimental: it has not been scripted in a full audit yet, and it does not yet guarantee a plan for every finding in a planned module; `recommend` lists any finding id it got no plan for in `failed`.
- **Out of reach: security, load testing, observability.** The kit does not look for vulnerabilities, measure production behaviour or replace monitoring.
- **The evidence allowlist is not a sandbox**, and the agents read untrusted code. See [security](security.md).
- **A repo's `.git` folder is trusted input.** `kit pin` and `kit doctor` refuse a repo whose `.git` can start a program or fetch (the list is in [security](security.md)); `--trust-git-dir` skips the .git-folder check entirely (a .git file, commondir, alternates, core.worktree, includes, filter and diff drivers are then all allowed); the isolated git environment still applies. The choice is recorded at pin time and is not re-checked if the folder changes later. Worktree checkouts and submodules are refused unless you use that flag.
- **`.env` is handled by file name only.** A file or folder named .env, or .env followed by '.', '-' or '_' (any case), is never read by name and is excluded from folder searches (grep, rg, git grep). `git show` and `git diff` always get the same excludes, and `git log` gets them with patch or file-list output (`-p`, `--stat`, `--unified` and the like); a file operand that is a link to such a file is refused. The kit never promises that a secret cannot reach a receipt: the output detectors are the last line, and a withheld output is the signal to look. The detectors are patterns for home paths, credentialed URLs, JWTs, payment keys, cloud keys, private keys, token prefixes and email addresses, so a secret of another shape can reach a receipt.
- **Known, not fixed yet:** reading a `.env` file by its object id (`git ls-tree` shows the id; `git cat-file -p <id>` or `git show <id>` prints it, since pathspecs never apply to a blob), and `git log --follow` or `-L` (git takes no extra pathspec there, so a `.env` renamed to another name can show its old contents). For these the output detectors are the only check.
- **Evidence glob and path rules err on the side of refusing.** A glob after `--` or `-g` that could match an `.env` file is refused, and so is a file pattern placed after the first operand (the search pattern or the first path). `kit evidence --dry-run` lists what is skipped and why.
- **Deny rules are a layer, not a boundary.** Bare `node` cannot be denied, and an unquoted git subcommand word in a search (`git grep config`) matches a deny rule: quote it or use `rg`. See [security](security.md).
- **Generated pages escape agent text only in part.** Agent-written text in prose and table cells has `<` and `![` escaped, and a Markdown link is kept only when its target is `http:`, `https:`, `mailto:`, an anchor (`#…`) or a plain relative path; any other link is broken into plain text. A reference-style definition (`[b]: target` alone on a line) is not checked. Read generated pages before sharing them, and do not open links you do not recognise. In the tracker CSV, a cell that starts with `=`, `+`, `-` or `@` gets a leading quote so a spreadsheet does not read it as a formula; the quote shows in the imported text.
- **macOS is not in the per-push checks.** CI runs on pushes to `main` and pull requests into `main`, on Ubuntu and Windows; the `macos-latest` job runs only when someone starts it by hand.
